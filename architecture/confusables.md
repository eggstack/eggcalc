## Purpose

Contains the confusables table derived from Unicode Standard Annex #39 (UTS #39) for detecting homoglyph attacks. This is an auto-generated file (~40KB) containing a zlib-compressed base85 payload and a lazy `_LazyConfusables` mapping (6565 entries). Data is decoded on first access, not at import time. Do not edit manually.

## Data Source

Generated from the official Unicode `confusables.txt` file:

- **URL:** https://www.unicode.org/Public/security/latest/confusables.txt
- **Source Version:** 17.0.0
- **Source Date:** 2025-07-22, 05:49:37 GMT
- **Generated:** 2026-05-29
- **Entry Count:** 6565

## Data Structure

The file exports a lazy `Mapping` that decodes a compressed payload on first access:

```python
CONFUSABLES: Mapping[str, str] = _LazyConfusables()
```

The `_LazyConfusables` class stores a zlib-compressed base85 payload and decodes it into a `dict[str, str]` on first access. After decoding, the dict is cached for subsequent lookups. The mapping supports `__getitem__`, `__contains__`, `__iter__`, and `__len__`.

**Keys** are uppercase hex codepoints prefixed with `U+` (e.g., `"U+0430"`). **Values** are space-separated `U+XXXX` sequences representing the confusable equivalent — this may be a single codepoint or multiple codepoints.

Character names are resolved at runtime via `unicodedata.name()`; the file contains only codepoint mappings.

## Generating the Table

The `confusables.py` file is generated by `scripts/generate_confusables.py`. To regenerate:

```bash
python scripts/generate_confusables.py
```

This reads the Unicode `confusables.txt` file and produces the `CONFUSABLES` dictionary. The file header contains metadata about the source version and generation date.

**Do not** edit `confusables.py` directly — any manual changes will be overwritten on regeneration.

## How Confusables Work

Each entry maps a character that may be used to impersonate another character to its confusable equivalent(s). The mapping is used by `unicode_tools.detect_confusables()` to scan text for characters that visually resemble other characters.

- **1:1 mapping:** A single character looks like another single character (e.g., Cyrillic `а` → Latin `a`)
- **1:N mapping:** A single character looks like a sequence of characters (e.g., `Æ` → `AE`)

When scanning text, each character is looked up in this table. If found, the character is flagged as a potential confusable.

## Security Applications

This table enables detection of:

- **Homoglyph attacks:** `"pаypal"` (Cyrillic `а`) visually resembles `"paypal"`
- **IDN homograph attacks:** Internationalized domain names using visually identical characters from different scripts
- **Social engineering:** Using similar-looking characters in identifiers, URLs, or user-facing text to mislead users

## Usage in the Codebase

The `CONFUSABLES` dictionary is consumed by:

- `unicode_tools.detect_confusables(text: str) -> list[ConfusableInfo]` — scans text and returns a list of detected confusable characters with their equivalents
- `synthesis.inspect_text()` — calls `detect_confusables()` when `include_confusables=True` (default)
- `synthesis.explain_diff()` — calls `detect_confusables()` to report confusable security findings
