The official 2026-07-28 specification describes modern MCP as stateless,
with protocol version and client capabilities in every request's `_meta`, and
requires `server/discover`; it also says discovery is optional for a client
and is the recommended stdio backward-compatibility probe. Eggcalc matches
that request-local model. The TypeScript SDK's stdio implementation pins the
selected era for a connection after its opening probe; that is SDK connection
policy, not a requirement for eggcalc to persist client state. No code change
was needed.

The Inspector one-shot CLI does not expose `server/discover` as a selectable
method, but its modern configured connection performed the modern opening
probe successfully. The raw core probe directly exercised
`server/discover`. Inspector also reported schema-portability warnings for
some tool schemas; these are advisory warnings from the client-side
portability linter, not wire validation failures, and the official core
schemas accepted the responses.

## Held-out agent evaluation

The 60 held-out cases were run once for each of five configurations against
two materially different model families through a local OpenAI-compatible
gateway. The runner exposed the actual serialized `tools/list` definitions;
the discovery configuration added the top five deterministic lexical matches
not already in `agent_core`. Rollouts were one-turn tool-selection probes and
were scored offline with `scripts/score_mcp_tool_selection.py`.

`acceptable_anywhere` means at least one selected tool was in the case's
acceptable primary/supporting set. `first_tool` requires the first selected
tool to be an acceptable primary. Empty-acceptance cases correctly reward no
tool call. The runner did not execute selected tools or assess final answer
correctness, so `task_correct` is deliberately unreported.

The result does not satisfy Plan 041's non-inferiority/recovery gate:

- `agent_core/compact` trails the best full/compact baseline on both model
  families.
- Discovery improves the static core result for both families, but remains
  below the corresponding full baseline and is not close enough to call the
  specialist recovery gate passed.
- No recurring invalid-name, invalid-argument, or redundant-call problem was
  observed, so there is no evidence for a new composite or a schema repair.

The conclusion is therefore to retain the current 10-tool profile and lexical
discovery implementation as an opt-in experiment, keep `full` as the
compatibility default, and defer any permanent “recommended general agent”
claim until a future evaluation redesign or catalog correction produces
non-inferior held-out behavior. Held-out expectations were not edited.
